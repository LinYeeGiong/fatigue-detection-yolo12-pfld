# 基于改进 YOLO12 的疲劳驾驶检测系统技术说明

## 1. 系统概述

系统采用“人脸检测 + 面部关键点 + 时序疲劳判定”的级联方案。改进 YOLO12 负责从图片或视频帧中定位驾驶员人脸，PFLD 负责预测 98 个面部关键点以及 Pitch、Roll、Yaw 三轴头部姿态。系统根据关键点计算眼睛纵横比 EAR、嘴部纵横比 MAR，并结合俯仰角、行为持续时间和 60 秒滑动窗口内的出现频次，将状态划分为正常、轻度、中度和重度。

系统支持批量图片、上传视频逐帧分析和摄像头实时监测。检测结果可保存至本地数据库，并生成风险分布、行为统计、任务趋势、指标趋势和视频性能分析图表。

## 2. 模型与数据集

### 2.1 改进 YOLO12 人脸检测模型

人脸检测数据以 **WIDER FACE** 为基础。原始训练集包含大量拥挤场景，与车内单驾驶员场景差异较大，因此执行以下处理：

1. 删除单张图片中人脸数量超过 5 个的拥挤样本，降低场景偏差。
2. 统一转换为 YOLO 标注格式，并检查空标注、越界框和异常宽高。
3. 最终得到训练图片 8,331 张、验证图片 2,044 张，对应标签数量一致。
4. 训练阶段使用缩放、翻转、颜色扰动、亮度变化等增强，提高复杂光照下的泛化能力。

模型输入尺寸为 `640 x 640`，训练参数为 150 epochs、batch size 64。网络以轻量化 YOLO12 为基线，在特征提取结构中融合 C3k2-DEConv，并加入无参数 SimAM 注意力模块，以增强暗光、模糊及局部遮挡条件下的人脸特征表达。训练完成后导出为 ONNX，用于桌面端和 Docker 统一推理。

### 2.2 PFLD 关键点与姿态模型

PFLD 使用 **WFLW（Wider Facial Landmarks in the Wild）** 数据集。WFLW 提供 98 点面部关键点标注，并包含姿态、表情、光照、化妆、遮挡和模糊等复杂子集。

处理流程包括：依据人脸框裁剪并适当外扩、将人脸缩放至 `112 x 112`、BGR 转 RGB、归一化至 `[0, 1]`。训练增强采用 0.2 概率随机灰度、亮度/对比度/饱和度/色相扰动，以及 0.2 概率随机擦除。模型联合学习 98 点坐标和 Yaw、Pitch、Roll 姿态角，使用 Adam 优化器、Wing Loss 与姿态损失。验证指标包括关键点 NME、瞳间归一化误差和姿态角 MAE，最终同样导出为 ONNX。

> 当前交付程序直接加载已有 ONNX 权重，不在客户电脑上执行训练。

## 3. 推理与疲劳判定流程

每帧图像先经等比例缩放和填充后输入改进 YOLO12，经过置信度过滤与 NMS 得到人脸框。人脸区域外扩约 10% 后送入 PFLD，得到关键点和三轴姿态。系统计算 EAR、MAR 和 Pitch：EAR 过低表示闭眼，MAR 过高表示哈欠，Pitch 偏移过大表示低头。

静态图片只输出当前帧状态；视频和摄像头为不同任务创建独立时序会话。连续闭眼、频繁哈欠或持续低头会逐级提高风险。视频通过 SSE 按源顺序推送每一个可解码帧的标注图、进度、指标、FPS 和单帧延迟。重度状态采用右上角非阻塞通知，不中断视频处理。

## 4. 系统技术栈

| 层级 | 技术 | 作用 |
| --- | --- | --- |
| 推理 | Python 3.11、ONNX Runtime、NumPy | 加载双模型，支持 CPU 和可选 CUDA |
| 图像处理 | OpenCV | 解码、缩放、NMS、逐帧读取与结果绘制 |
| 后端 | Flask 3、Waitress | 页面、REST API、SSE 视频流与文件上传 |
| 前端 | Jinja2、HTML5、CSS、原生 JavaScript | 检测工作台、实时指标、历史记录与交互 |
| 图表 | Chart.js、Lucide Icons | 统计图表、PNG 导出和统一图标 |
| 桌面端 | Electron、electron-builder | Windows 桌面窗口、后端进程管理和 NSIS 安装包 |
| 数据库 | SQLite | 本地持久化检测任务及分析数据 |
| 部署 | Docker Compose | CPU 一键启动，并提供可选 GPU 配置 |

前后端部署在同一本地服务中，不依赖公网。Electron 启动时选择空闲端口、拉起后端并等待 `/api/health` 就绪；关闭桌面程序时同步结束后端进程。

## 5. 数据库设计

SQLite 数据库文件为 `fatigue.db`，核心表为 `records`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | INTEGER | 自增主键 |
| `source_type` | TEXT | 输入来源：image、video 或 camera |
| `source_name` | TEXT | 图片或视频文件名 |
| `level` | TEXT | normal、mild、moderate、severe |
| `score` | INTEGER | 任务风险分值 |
| `details` | TEXT | JSON 格式的完整检测与实验信息 |
| `created_at` | TEXT | UTC ISO 8601 创建时间 |

`details` 根据来源保存 EAR、MAR、Pitch、事件列表等数据；视频还保存总帧数、实际处理帧数、等级分布、事件次数、时间线、平均 FPS 和平均延迟。统计接口直接聚合这些真实记录，CSV、PNG 和 PDF 导出均基于数据库结果，不生成无标注依据的 mAP、Precision 或 Recall。

## 6. 部署与运行

Windows 主交付为 Electron 安装包，CPU 环境即可运行；检测到可用 CUDA Provider 时可使用 GPU。附加部署方式为：

```powershell
docker compose up --build
```

启动后访问 `http://localhost:5001`。模型权重、应用数据和上传临时文件均保存在本地，适合离线演示和实验验收。
